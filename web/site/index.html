How the check works, and what it does not show
  • The contract stores the hash and logs it in a policy_set event with the epoch and the rate. The chair also sends the reasoning text as an extra argument of the same set_policy call. The contract ignores it, but it stays in the transaction, so it is public.
  • This page reads that text from the transaction's arguments. Decisions made before the chair sent it have no text there: for those, the chair's own saved text is used, copied into this page's files when the page is built, from the docs/ folder of the repo. Nothing is fetched from a model or a server of mine.
  • Your browser computes the SHA-256 of the exact text shown and compares it with the hash read from the chain. Verified means the text matches that hash. A text read from the transaction sits in the same transaction as the hash, so it cannot be quietly rewritten afterwards. A decision with neither text shows its hash only.
  • A match does not show the chair was right, that the text is the real reason for the rate, or that an AI wrote it: the contract stores only a hash the chair supplies. It shows the text was not edited after the decision.

What the contract guarantees

Check it yourself with one command from a clone of the repo. It runs the real contract in a local NEAR sandbox and fails if any administrative method exists.

For a deployed account, anyone can also ask any RPC node for its access keys. The answer must be an empty list, which is also shown in the supply ledger.

What this page does not prove
  • It does not say the chair is wise. The contract bounds the chair; it does not make it right.
  • It does not say a bad Chair cannot do harm. A Chair that prints at its ceiling keeps doing so for as long as the holders let it. What stops it is the holders; see "What if the Chair went rogue?".
  • It does not say anything about price, liquidity or returns. The simulation is a model of supply under stated assumptions.
  • The log comes from an index, so it is checked, not signed: its sums must equal the chain's own ledger, and a difference is shown as such. Each row links to its transaction so you can check any entry by hand.

$CHAIR is a hackathon project and a toy monetary experiment. Nothing here is advice. The transfers, stakes and claims in the log are scripted test activity by three accounts I control, not users, plus test accounts funded by the faucet for page visitors.
