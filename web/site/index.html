$CHAIR
Rate Ledger Log Simulation Guarantees

A token whose supply is steered by a chair built for an AI agent, on a leash the contract holds.

Once per epoch the chair picks a rate. A positive rate mints new tokens for stakers, a negative rate burns a share of every transfer. The contract limits the rate and the size of each move, and it works the same whether or not a chair is listening. This page is every mint and burn the contract has made, checked against its own books.

Sixty epochs under five chairs

The same contract rules run for 60 epochs under five behaviours of the chair. With one-day epochs that is 60 days; the epoch length is a launch setting, and the simulation only counts epochs. It is the repo's own simulator (sim/) running in your browser, not a recording.

What the contract guarantees

Check it yourself with one command from a clone of the repo. It runs the real contract in a local NEAR sandbox and fails if any administrative method exists.

For a deployed account, anyone can also ask any RPC node for its access keys. The answer must be an empty list, which is also shown in the ledger above.

What this page does not prove

  • It does not say the chair is wise. The contract bounds the chair; it does not make it right.
  • It does not say anything about price, liquidity or returns. The simulation is a model of supply under stated assumptions.
  • The log comes from an index, so it is checked, not signed: its sums must equal the chain's own ledger, and a difference is shown as such. Each row links to its transaction so you can check any entry by hand.

$CHAIR is a hackathon project and a toy monetary experiment. Nothing here is advice.
